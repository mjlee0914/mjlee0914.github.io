스크롤할 때 상단 헤더가 사라지는 과정

처음에는 위쪽 영역과 아래 메뉴 영역을 따로 만들고, 아래 메뉴에만 `sticky`를 적용했다.

```html
<section class="header1">
  <!-- 로고, 로그인 등 위쪽 영역 -->
</section>

<section class="header2">
  <!-- 강의 메뉴 -->
</section>
```

```css
.header2 {
  position: sticky;
  top: 0;
}
```

이 방식에서는 `header2`가 화면 맨 위에 닿는 순간부터 그것만 고정된다. **메뉴를 계속 보이게 하는 것**이 목표라면 CSS만으로 끝나므로 이 방법이 더 간단하다.

선생님이 적용한 방식은 `sticky`를 대체한 것이 아니라, 스크롤 위치에 따라 헤더의 모습을 바꾸는 기능을 추가한 것이다.

1) HTML: 두 영역의 공통 부모 만들기

```html
<header class="site-header">
  <section class="section1">
    <!-- 로고, 로그인 등 위쪽 영역 -->
  </section>

  <section class="section2">
    <!-- 강의 메뉴 -->
  </section>
</header>
```

`header1`, `header2`를 `section1`, `section2`로 바꾼 것 자체가 동작을 바꾸지는 않는다. 중요한 점은 두 영역을 `<header>`라는 **하나의 부모**로 감싼 것이다. 이제 CSS와 JavaScript가 두 영역을 각각이 아니라 `header` 전체에 적용될 수 있다.

`<header>`는 페이지의 머리말이라는 뜻을 가진 시맨틱 태그다. 기능만 보면 `<div class="site-header">`도 같은 방식으로 동작하지만, 이 경우에는 `<header>`가 더 의미에 맞다.

2) JavaScript: 스크롤 위치에 따라 `fixed` 클래스 붙이기

```js
const header = document.querySelector(".site-header");

window.addEventListener("scroll", () => {
  if (window.scrollY >= 40) {
    header.classList.add("fixed");
  } else {
    header.classList.remove("fixed");
  }
});
```

JavaScript가 헤더를 직접 위로 움직이는 것은 아니다.

1. 사용자가 스크롤한다.
2. `scroll` 이벤트가 실행된다.
3. `window.scrollY`가 `40` 이상이면 `header`에 `fixed`라는 클래스를 붙인다.
4. 다시 `40`보다 위로 올라오면 그 클래스를 뗀다.

즉, JavaScript의 역할은 **현재 스크롤 위치를 보고 헤더의 상태 이름(`fixed`)을 바꿔 주는 것**이다.

3) CSS: `fixed` 상태의 헤더를 고정하고 위로 밀기

```css
.site-header {
  transition: transform 0.5s ease;
}

.site-header.fixed {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  z-index: 100;
  transform: translateY(-42px);
}
```

`fixed` 클래스가 붙은 뒤에는 CSS가 화면 변화를 만든다.

- `position: fixed`: `header` 전체를 화면 기준으로 고정한다.
- `top: 0`: 고정된 `header`의 시작 위치를 화면 맨 위로 둔다.
- `transform: translateY(-42px)`: `header` 전체를 위로 `42px` 올린다.

여기서 `42px`은 위쪽 영역(`section1`)의 높이에 맞춘 값이다. `header` 전체를 위로 올리면 `section1`은 화면 밖으로 사라지고, 아래쪽 `section2`만 화면 안에 남는다.

```text
처음
[ section1: 로고 / 로그인 ]
[ section2: 강의 메뉴 ]

40px 이상 스크롤 후
[ section1 ]  ← header 전체가 위로 42px 이동하여 화면 밖으로 감춤
[ section2: 강의 메뉴 ]  ← fixed 상태로 화면 상단에 남음
```

Sticky와 JS 방식의 차이

| 방식 | 고정되는 대상 | 가능한 동작 | 적합한 경우 |
| --- | --- | --- | --- |
| `position: sticky` | `header2` 하나 | 메뉴를 상단에 고정 | 메뉴 고정만 필요할 때 |
| JS + `fixed` 클래스 | `header` 전체 | 상단 영역 숨김, 색상·높이·애니메이션 등 상태 변경 | 스크롤에 따라 헤더를 다르게 보이게 할 때 |

내가 사용한 `sticky` 방식은 틀린 방법이 아니다. 단순히 메뉴만 고정한다면 더 쉽고 좋은 선택이다. 선생님 방식은 **“상단 로고 영역은 사라지고 메뉴만 남게 하기”**라는 추가 연출이 필요해서 JavaScript로 클래스를 붙이고 CSS 상태를 바꾼 것이다.

> `position: fixed`가 되면 헤더가 일반 문서 흐름에서 빠진다. 그 때문에 아래 콘텐츠가 위로 튀는 경우에는 헤더 높이만큼의 여백(spacer 또는 `padding-top`)을 추가해야 한다.

#### media query (@media...)
```html
@media 미디어타입(장비종류) and (미디어특성 - breakpoint 설정을 주로 지정) {
    /* css 정의(@media에 붙인 조건이 참일때만 실행할 css code)*/
}

ex)

@media screen and (min-width: 768px) {
  body { background-color: lightgreen; }
}
/* 출력 대상 기기가 스크린(모니터/스마트폰)이고, 화면 가로폭이 최소 768px 이상일 때 배경색을 연초록색으로 바꿉니다. */
```

미디어타입
- all: 모든 미디어 장치
- screen: 스크린이 있는 모든 기기
- print: 프린트
- speech: 스크린리더기

기기별 권장 사양 breakpoint -> 기준에 따라 css 적용이 달라짐.
- 모바일
    - max-width: 767px
- 태블릿
    - min-width: 768px
    - max-width: 1023px
- 데스크탑
    - min-width: 1024px
