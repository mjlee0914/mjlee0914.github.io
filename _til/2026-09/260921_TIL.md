#### Node.js

- JavaScript를 **브라우저 밖에서도 실행할 수 있게 해주는 Runtime Environment**
- Open-source + Cross-platform
- 주로 **Back-end / Server-side JavaScript** 개발에 사용

```text
Browser
→ Front-end
→ Client-side JavaScript

Node.js
→ Back-end
→ Server-side JavaScript
```

- Browser와 Node.js는 목적이 다르기 때문에 사용할 수 있는 **API도 다름**

#### Global Object
![Browser, Node.js, globalThis 전역 객체 비교](../image-25.png)
JavaScript의 전역 객체는 실행 환경에 따라 다르게 접근할 수 있음.

```text
공통        → globalThis
Browser     → window
Node.js     → global
```

- `globalThis`
  - Browser와 Node.js 둘 다 사용 가능
  - 현재 권장 방식

- `window`
  - Browser 환경의 global object
  - DOM, cookie, browser event 등 브라우저 기능에 접근

- `global`
  - Node.js 환경의 global object
  - 파일, 네트워크, OS 관련 기능에 접근
  - 현재는 legacy API로 분류되어 `globalThis` 사용 권장

#### 한 줄 정리

> `Node.js` = JavaScript를 브라우저 밖, 특히 서버에서 실행할 수 있게 해주는 Runtime Environment

> Global object는 환경에 관계없이 `globalThis`를 사용하는 것이 가장 권장됨

#### var의 3가지 결함
- 호이스팅 (Hoisting)
- 선언 키워드 생략 허용 (암묵적 전역 변수): var(선언자) 생략하고 변수를 지역변수로 정의하면 전역변수가됨 (고립시켜야하는데 코드 전체에 적용됨)
- 함수 레벨 스코프 (Function-level Scope): 전역변수 오염 문제 발생 => 대신 let 사용
  
---> ES6+ 등장
    - const, let 사용 (블록 레벨 스코프)
    - let: 재할당 가능
    - const: 재할당 불가

```javascript
/// 함수 레벨 스코프 특징을 가진 var

function test() {
    if (true) {
        var x = 10;
    }

    console.log(x); // 10, var는 if(+ for) {}를 무시하고 함수 전체를 하나의 스코프로 봄. 
                    // 함수 내부에서만 지역 변수로 취급
}
```

```javascript
var i = 10000;

for (var i = 0; i < 10; i++) {
    console.log(i);
}

console.log(i); // 10. var로 정의된 i는 for 안의 별도 변수가 아닌 바깥 i와 같은 글로벌 변수로 취급됨.
```
- var: 함수 안-지역변수, 함수 밖-global scope 변수
- var는 for와 if에서 새로운 scope를 만들지 않음

```javascript
var x = 20; // global

function test() {
    if (true) {
        var x = 10; // test 함수의 local variable
    }

    console.log(x); // 10
}

test();

console.log(x); // 20
```
- 위 예시에서 함수 안 x(local var)는 함수 밖 x(global var)와 다름

#### Hoisting

`Hoisting`은 변수나 함수의 선언이 실제 코드 위로 이동하는 것이 아니라, **JavaScript가 코드를 실행하기 전에 Execution Context를 생성하면서 변수와 함수의 선언 정보를 먼저 등록하는 과정 때문에 나타나는 현상**이다.

```javascript

console.log(a);

var a = 10;
```

결과:

```text
undefined
```

코드를 실행하기 전에 Global Execution Context가 생성되면서 `var a`가 먼저 등록되고, 초기값으로 `undefined`가 설정된다.

개념적으로:

```javascript
var a = undefined;           // undefined

console.log(a);  // undefined

a = 10;
```

즉,

```text
코드 실행 전
↓
Execution Context 생성
↓
변수 / 함수 선언 정보 먼저 등록
↓
코드 실행
```

#### var Hoisting

`var`로 선언한 변수는 Execution Context가 생성될 때 `undefined`로 초기화된다.

```javascript
console.log(a); // undefined

var a = 10;

console.log(a); // 10
```

```text
EC 생성 시
a → undefined

실제 코드 실행 시
a → 10
```

따라서 `var`는 선언문보다 위에서 접근해도 `ReferenceError`가 발생하지 않고 `undefined`가 나온다.

#### let / const Hoisting

`let`, `const`도 선언 정보 자체는 Execution Context 생성 시 등록되므로 **Hoisting은 발생한다.**

하지만 `var`와 다르게 바로 `undefined`로 초기화되지 않고 `uninitialized` 상태로 존재한다.

```javascript
console.log(a);

let a = 10;
```

결과:

```text
ReferenceError
```

```text
var
→ 선언 등록
→ undefined로 초기화
→ 선언문 이전에도 접근 가능

let / const
→ 선언 등록
→ uninitialized 상태
→ 선언문 이전 접근 불가
```

`let`, `const`가 선언되기 전까지 접근할 수 없는 영역을 **TDZ(Temporal Dead Zone)** 라고 한다.

#### Function Hoisting

함수 선언문도 Execution Context 생성 시 함수 자체가 미리 등록된다.

```javascript
hello();

function hello() {
    console.log("Hello");
}
```

따라서 함수 선언문보다 위에서 함수를 호출할 수 있다.

```text
Execution Context 생성
↓
hello → 함수 자체 등록
↓
실제 코드 실행
↓
hello() 호출 가능
```

#### arrow function의 경우
```javascript
console.log(`sumFunc(1, 2) => ${sumFunc(1, 2)}`)
console.log(`sumConst(3, 4) => ${sumConst(3, 4)}`)

function sumFunc(a, b) { // 정상 동작
    return a + b
}

const sumConst = (a, b) => a + b // ReferenceError
```
#### Execution Context 관점

```javascript
let gb = 'global variable';

function func1() {
    console.log('start func1');
    func2();
    console.log('end func1');
}

function func2() {
    console.log('func2');
}

func1();

console.log('global execution context');
```

EC가 만들어지는 순서:

![JavaScript Execution Context 생성 순서](../image-26.png)

따라서 Hoisting은 단순히

> "변수가 코드 위로 올라간다"

라고 이해하기보다,

> **JavaScript가 코드를 실행하기 전에 Execution Context를 만들면서 선언 정보를 먼저 등록하기 때문에 발생하는 현상**

이라고 이해하는 것이 더 정확하다.

#### 한 줄 정리

> `Hoisting` = Execution Context가 생성될 때 변수와 함수의 선언 정보가 실제 코드 실행보다 먼저 등록되어, 선언이 위로 끌어올려진 것처럼 보이는 현상

```text
var        → Hoisting + undefined 초기화
let/const  → Hoisting + uninitialized → TDZ
function   → Hoisting + 함수 자체 등록
```

#### LangChain Runnable

`Runnable` = LangChain에서 **input → 처리 → output**을 수행하는 실행 단위

- Prompt, Model, OutputParser 등이 Runnable
- `.invoke()`로 실행
- `|` 연산자로 연결해서 Chain/Pipeline 구성 (RunnableLambda)

```text
input
  ↓
Runnable
  ↓
output
```

#### RunnableLambda / @chain

일반 Python 함수를 Runnable로 변환해서 Chain에 연결할 수 있음.
앞선 chain이 Runnable이면 다음 함수는 자동으로 Runnable

```python
from langchain_core.runnables import chain

@chain
def func_a(message: str) -> str:
    return f"func_a:{message}"
```

```python
chain = func_a | func_b
chain.invoke("안녕하세요!")
```

```text
안녕하세요!
↓
func_a
↓
func_b
↓
최종 결과
```

#### Runnable 실행 방식

| 동기 | 비동기 | 기능 |
|---|---|---|
| `invoke()` | `ainvoke()` | 입력 1개 처리 |
| `stream()` | `astream()` | 결과를 chunk 단위로 순차 반환 |
| `batch()` | `abatch()` | 여러 입력 처리 |

##### invoke

```python
chain.invoke("안녕하세요")
```

- 입력 1개 → 결과 1개
- 일반 실행 방식

##### stream

```python
for chunk in chain.stream("안녕하세요"):
    print(chunk, end="")
```

- 결과가 생성되는 대로 `chunk` 단위로 반환 (순서대로 조금씩)
- 사용자에게 실시간으로 답변을 보여줄 때 유용

##### batch

```python
messages = [
    "나의 전화번호는 010-1010-0000입니다. 당신의 번호는?",
    "안녕하세요!",
    "반갑습니다."
]

for i, res in enumerate(chain.batch(messages)):
    print(i, res)
# 결과: 인덱스 + 답변

chain.batch(messages)
# 결과: []안 답변
```
![LangChain batch 실행 결과](../image-29.png)
- 여러 입력을 한 번에 처리

##### async

```python
async for chunk in chain.astream("안녕하세요"):
    print(chunk, end="")
```

- `ainvoke()`, `astream()`, `abatch()`
- 다른 작업을 기다리면서 동시에 처리할 수 있는 비동기 방식

#### 개인정보 마스킹 Pipeline

Regex로 전화번호를 모델에 전달하기 전에 마스킹할 수 있음.

```python
import re # 정규표현식(Regex)을 사용하기 위한 Python 기본 모듈

def protected_message(message):
    pattern = re.compile(r"(010)\D*(\d{4})\D*(\d{4})")
    return pattern.sub(r"\g<1>-****-****", message)
```

```text
010-1234-5678
↓
010-****-****
```

```python
from langchain_core.output_parsers import StrOutputParser

```

#### 전체 Pipeline

```python
pipeline = protected_message | model | parser
```

```text
사용자 입력
↓
protected_message
- 개인정보 마스킹
- HumanMessage 변환
↓
model
- LLM 응답 생성
↓
StrOutputParser
- AIMessage → str
↓
최종 문자열
```

#### 핵심 정리

```text
Runnable
→ LangChain의 실행 단위

|
→ Runnable들을 연결

invoke()
→ 입력 1개

stream()
→ 실시간 chunk 출력

batch()
→ 여러 입력 처리

a + method
→ 비동기 버전

@chain / RunnableLambda
→ 일반 Python 함수도 Runnable로 변환

StrOutputParser
→ AIMessage → str
```

> 핵심: LangChain은 여러 `Runnable`을 `|`로 연결하여 하나의 데이터 처리 Pipeline을 만드는 구조이다.
