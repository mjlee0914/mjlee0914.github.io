## 1. TypeScript Checks Before Runtime

TypeScript extends JavaScript with a static type system. The compiler checks types during development and transforms TypeScript into JavaScript, which is what the JavaScript engine runs. This source-to-source transformation is commonly called **transpilation**; `tsc` is still the TypeScript compiler. Type annotations are removed and do not add runtime validation.

Type inference can determine a variable's type from its initial value. Explicit annotations are useful when a function or data structure needs a clear contract.

## 2. Primitive Types, Arrays, and Tuples

TypeScript includes primitive types such as `string`, `number`, `boolean`, `null`, and `undefined`. Arrays can be written as `number[]` or `Array<string>`. A tuple describes a fixed sequence whose positions have specific types:

```ts
const student: [string, number, boolean] = ["Kim", 12345, true];
```

An array usually allows a variable number of values of one element type. A tuple is useful when each position has a distinct meaning and type.

## 3. Handle Unknown Data Safely

`any` turns off type checking for a value, so mistakes can pass compilation. `unknown` can hold any value, but TypeScript requires the code to check its type before using type-specific operations:

```ts
function formatAmount(value: unknown): string {
  if (typeof value === "number") {
    return value.toFixed(2);
  }
  return "Invalid amount";
}
```

`never` represents a function that cannot return normally, such as one that always throws. A type assertion such as `value as string` only changes what the compiler assumes; it does not convert or validate the runtime value.

## 4. Describe Function Contracts

Function parameter and return annotations make inputs and outputs explicit. Optional parameters use `?` and may be `undefined`; rest parameters collect zero or more arguments into an array. Function type aliases describe callbacks and other functions passed around as values:

```ts
type PriceConverter = (price: number) => number;

const applyDiscount: PriceConverter = (price) => price * 0.9;
```

## 5. Define Object Shapes

`type` aliases and `interface` declarations describe the properties an object can have. Optional properties use `?`, while `readonly` prevents reassignment through that typed reference. Index signatures describe objects with keys that are not known in advance. Interfaces can extend other interfaces and declarations with the same name can merge.

For a shop product specification, an interface makes the expected fields visible and reusable:

```ts
interface Product {
  readonly id: number;
  name: string;
  price: number;
  stock: number;
  category?: string;
}

const notebook: Product = {
  id: 101,
  name: "Grid Notebook",
  price: 4500,
  stock: 24,
};
```

### Property Descriptors, Getters, Setters, and Symbols

To inspect property metadata, use `Object.getOwnPropertyDescriptors(object)` for all own properties or `Object.getOwnPropertyDescriptor(object, key)` for one. A data descriptor includes `value` and `writable`; an accessor descriptor uses `get` and `set`.

Getters and setters provide property-style access while allowing validation at the boundary:

```ts
class ServerConfig {
  private _baseUrl = "";

  get baseUrl(): string {
    return this._baseUrl;
  }

  set baseUrl(value: string) {
    if (!value.startsWith("https://")) {
      throw new Error("The URL must use HTTPS.");
    }
    this._baseUrl = value;
  }
}
```

Each `Symbol()` call creates a distinct key, even when two symbols use the same description. TypeScript's `unique symbol` type preserves the identity of one particular symbol for typed keys.

## 6. JavaScript and DOM Review

### Event Listeners

`addEventListener()` registers a handler; `removeEventListener()` removes it when the interaction or component is no longer needed. Keep a reference to the same named function so it can be removed. This also avoids registering fresh anonymous closures every time a component is rendered.

```js
function handleClick() {
  console.log("Clicked");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

### Reflow, Repaint, and `DocumentFragment`

A change to an element's size or position can require layout recalculation (often called **reflow**) and then painting. A paint-only change, such as text color, can repaint pixels without recalculating layout.

`DocumentFragment` lets code build a group of nodes outside the active document and append the group together. It can make batch updates easier to organize; modern browsers may already optimize repeated DOM work, so the speed benefit is not guaranteed.

```js
const fragment = document.createDocumentFragment();

for (const label of labels) {
  const item = document.createElement("li");
  item.textContent = label;
  fragment.append(item);
}

list.append(fragment);
```

- **`this` (B):** A regular function's `this` depends on how it is called. An arrow function has no own `this` and uses the value from its surrounding lexical scope.
