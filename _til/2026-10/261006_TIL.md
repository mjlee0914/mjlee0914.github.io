## Reflection

Today's practice connected TypeScript's type system to reusable program design. Union and literal types describe which values are valid; type guards choose the right behavior for each value; generics reuse one algorithm while preserving the input type; and classes and interfaces organize shared data and behavior. These are different layers of abstraction, and each helps make invalid states or repeated logic easier to control.

## 1. Model Valid Values with Unions, Intersections, and Literals

A union (`|`) accepts a value from one of several types. The book example allows an identifier to be either text or a number, while the availability status accepts only `AVAILABLE` or `RENTED`. A literal union makes the permitted states explicit, so a value such as `SUBMITTED?` is rejected by the TypeScript checker.

An intersection (`&`) combines requirements. `ClubStudentProfile` must include the fields from both `StudentProfile` and `ClubMember`; `DetailedAssignment` combines the base assignment fields with a `SubmitStatus`. This lets a larger model reuse smaller, named shapes instead of repeating their fields.

## 2. Narrow a Union Before Using Its Specific Fields

A union says what a value could be. A type guard establishes which case is present at a particular point in the code:

- `typeof score === 'number'` narrows `string | number`, allowing numeric arithmetic only in the number branch.
- `'code' in coupon` narrows a coupon to the shape that has a `code`; checking `discountPercent` selects the other coupon shape.
- An order's `status` literal is a discriminant. The `switch` branches handle pending, shipped, and delivered states while using one `OrderState` parameter type.

The follow-up calls pass object literals directly to `processOrder`, showing that callers can use the shared operation without first declaring a separate variable for each state.

## 3. Generalize Operations with Generics

A generic type parameter such as `T` stands for a type chosen when the function or interface is used. `getLastElement<T>` can return the last item from number and string arrays without duplicating the algorithm. Unlike `any`, the generic keeps the relationship between an input's type and the returned value's type. The empty-array branch returns `undefined`.

`StorageBox<T>` and `DataContainer<T>` apply the same idea to object shapes. The box can contain a `Product`, while `wrapData<T>` creates the same timestamp-and-value structure for numbers, booleans, or strings. The calls in the notebook demonstrate those three value types.

A constraint such as `T extends HasPrice` keeps a generic flexible while requiring the one property its algorithm needs. `keyof StudentInfo` forms a union of valid property names. The `getCourseValue<T, K extends keyof T>` function combines that constraint with `T[K]`, so a requested key must belong to the object and its return type matches that property's type. The exercise defines this helper and separately logs the course title and credit; it does not call the helper in the notebook.

## 4. Organize Shared Behavior with Classes and Contracts

The `Book` class keeps its price private and changes it through `setPrice`, where negative values are ignored. Its public title and `printInfo` method form the part callers can use. TypeScript's constructor parameter properties also declare and initialize fields in one place.

`Coffee` extends `Beverage` to reuse the common name and price while adding a private shot count; `super` initializes the parent fields. `VIPUser` overrides `addPoint` to apply its own rule. In this sample, a `bonusRate` of `30` is used as a multiplier: adding 20 points adds 600, resulting in 650 total points. If the intended meaning were 30 percent, the rate would need to be represented as `0.30` or divided by 100.

`Animal` is an abstract class: it provides the shared `printName` behavior and requires a concrete subclass such as `Dog` to implement `makeSound`. `Powerable` describes a capability rather than a particular device. Both `Television` and `AirConditioner` implement that contract, so the program can keep them in one `Powerable[]` and call `turnOn()` through the common interface.

The uploaded Chapter 7 lesson also covers `static` members and getters/setters. Static members belong to the class and are shared across its instances; getters and setters provide controlled access to properties. Those ideas complement the practice examples' use of private fields and methods, even though the practice notebook does not exercise them directly.

## 5. What Code Abstraction Means Here

Code abstraction means giving a useful name to a rule or capability and hiding details that callers do not need to repeat. It is more than shortening code: a good abstraction makes the program's intent clearer and gives changes a well-defined place.

The exercises show several levels of abstraction:

1. **Type abstraction:** `SubmitStatus`, `OrderState`, and `ClubStudentProfile` name valid domain shapes and value sets.
2. **Algorithm abstraction:** `getLastElement<T>` and `wrapData<T>` express one operation for many value types without losing type information.
3. **Constraint abstraction:** `HasPrice` and `K extends keyof T` state the minimum requirements that reusable functions depend on.
4. **Behavior abstraction:** `Powerable` lets code ask for the `turnOn` capability without depending on whether the device is a TV or air conditioner. The abstract `Animal` class shares behavior while leaving a sound implementation to each subclass.
5. **Encapsulation:** `Book` hides its price and exposes a method that controls how it changes.

Type aliases, interfaces, and generic parameters help the compiler check these contracts; they do not validate arbitrary data at runtime. Runtime checks such as `typeof`, `in`, and examining a discriminant are still useful when selecting behavior for values that exist at runtime. Abstraction is useful when the shared rule is clear; a one-off operation can remain direct when a reusable contract would make it harder to understand.

```typescript
// 5장 2강 문제 3-1 서로소 판별 유니온과 switch 문을 활용한 주문 상태 처리
type PendingOrder = {
    status: "pending"
}

type ShippedOrder = {
    status: "shipped"
}

type DeliveredOrder = {
    status: "delivered"
}

type OrderState = PendingOrder | ShippedOrder | DeliveredOrder;

function processOrder(state: OrderState) {
    switch (state.status) {
        case "pending":
            console.log("주문 대기 안내")
            break;

        case "shipped":
            console.log("운송장 번호 출력")
            break;

        case "delivered":
            console.log("배송 완료 날짜")
            break;
    }
}

const stateP: PendingOrder = {status: "pending"};
const stateS: ShippedOrder = {status: "shipped"};
const stateD: DeliveredOrder = {status: "delivered"};

processOrder(stateP);
processOrder(stateS);
processOrder(stateD);
```

```typescript
function getLastElement<T>(val: T[]) {

}
```

#### Chapter 7: Override point accumulation for a VIP user

```typescript
// 7장 1강 문제 3-1 VIP 회원의 포인트 적립 로직 오버라이딩

// parent class
class User {
    constructor(public userName: string, protected point: number) {}

    addPoint(amount: number) {
        return this.point += amount;
    }
}

class VIPUser extends User {
    // add property
    private bonusRate: number;

    constructor(userName: string, point: number, bonusRate: number) {
        super(userName, point);
        this.bonusRate = bonusRate;
    }

    addPoint(amount: number): number {
        let bonusNum = amount * this.bonusRate;
        return this.point += bonusNum;
    }
}

let userEx = new User("lee", 50);
userEx.addPoint(20);
console.log(userEx);

let vipEx = new VIPUser("kim", 50, 30);
vipEx.addPoint(20); // bounsNum = 600
console.log(vipEx);
```
