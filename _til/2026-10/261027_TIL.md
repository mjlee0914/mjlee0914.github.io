**pydantic**

- type hint + typing 양식 바탕
- 실행 중에 데이터 타입을 강제로 검사하고 올바르게 변환해 주는 문지기 역할을 함
- FastAPI가 요청 Body를 검사할 때 주로 사용

기능 및 문법

- `.model_dump()`, `.model_dump_json()`: 명칭 정리 및 데이터 추출 메서드를 일원화
- `field_validator`: Field()만으로 표현하기 어려운 특정 필드의 사용자 정의 검증
- `model_validator`: 데이터 조립 전/후 검증 단계 분석
- `BaseModel`
  - 기본 제공 데이터 양식(부모 클래스)
  - 내가 정의한 데이터 클래스에 상속시킴
  - 파이썬은 단순한 객체가 아닌 실행 중에 데이터 타입을 스스로 검사 가능한 데이터 schema가 됨
- `Field()`
  - BaseModel 내부에 선언할 각 데이터 칸에 구체적인 규칙 적어줌
  - ex) 필수 여부(...), default, default_factory, min/max_length, gt/ge, lt/le, description
    - default: 사용자가 값을 보내지 않았을 때의 기본값 설정 ex) `default=None`
    - default_factory: 기본값 생성 함수, 매번 새로운 객체가 독립적으로 만들어져야 할 때 ex) `default_factory=list`
    - gt / ge(grater or equal): 숫자 크기 제한 조건
    - lt / le (less or equal): "
    - description: 이 칸이 어떤 데이터인지 기록하는 메모. 웹 API 명세서 문서에 자동으로 연동되어 나타남

```python
import logging
from typing import Any, Optional, Self

from pydantic import BaseModel, Field, field_validator, model_validator

logger = logging.getLogger(__name__)

class BookCreate(BaseModel):
    # Field: 필드의 필수 여부, 길이, 범위, API 문서 설명 등을 선언한다.
    # ...은 필수 값이라는 뜻이다.
    title: str = Field(..., min_length=2, max_length=100, description="책 제목")
    author: str = Field(..., min_length=2, max_length=50, description="저자")
    # None은 선택 값, gt=0은 값이 있다면 0보다 커야 한다는 뜻이다.
    price: Optional[int] = Field(None, description="가격", gt=0)

    @model_validator(mode="before")
    @classmethod
    def before_validate(cls, data: Any) -> Any:
        # model before: 각 필드가 변환·검증되기 전의 원본 요청 전체를 받는다.
        logger.info("1. model_validator(before) 원본 요청: %s", data)
        return data

    @field_validator("title", "author", mode="before")
    @classmethod
    def trim_text(cls, value: Any) -> Any:
        # field before: Field의 타입·길이 검증 전에 원본 필드 값을 가공한다.
        logger.info("2. field_validator(before) 원본 필드: %r", value)
        if isinstance(value, str):
            return value.strip()
        return value

    @field_validator("title", "author", mode="after")
    @classmethod
    def check_validated_text(cls, value: str) -> str:
        # field after: 타입 변환과 Field 제약조건을 통과한 필드 값을 받는다.
        logger.info("3. field_validator(after) 검증된 필드: %r", value)
        return value

    @model_validator(mode="after")
    def after_validate(self) -> Self:
        # model after: 모든 필드 검증이 끝난 완성된 BookCreate 객체를 받는다.
        logger.info("4. model_validator(after) 완성된 모델: %s", self)
        return self

# 응답 형식 정의
class BookResponse(BaseModel):
    title: str
    author: str
    price: int
```

decorator
@classmethod

- 인스턴스가 아니라 클래스 자체를 첫 번째 매개변수로 받음
- first parameter = cls(class)
- 클래스 속성에 접근하거나 대체 생성자를 만들 때 사용
- classmethod를 넣어야 cls가 뭔지 함수가 알잘딱깔센으로 알아먹는다.
- 인스턴스에는 안 묶임, 클래스에는 묶임

@staticmethod

- 매개변수로 self나 cls 받지 않는 독립적인 메서드
- 특정 객체의 정보가 필요 없을 때
- 정적?: 특정 인스턴스에 묶이거나 클래스를 자동으로 매개변수로 전달받지 않는다.
- 전달받은 매개변수만 사용해서 동작한다.
- 인스턴스에도 안 묶임, 클래스에도 안 묶임

```python
from fastapi import FastAPI
from pydantic import BaseModel, field_validator, model_validator

app = FastAPI()

class BookCreate(BaseModel):
    title: str
    price: int
    discount_price: int

    # title 하나만 검사
    @field_validator("title", mode="before")
    @classmethod
    def clean_title(cls, value):
        print("title before:", value)

        # Pydantic이 검사하기 전에 공백 제거
        return value.strip()

    # price 하나만 검사
    @field_validator("price", mode="after")
    @classmethod
    def check_price(cls, value):
        print("price after:", value, type(value))

        if value < 0:
            raise ValueError("가격은 0 이상이어야 합니다.")

        return value

    # 모든 필드를 함께 검사
    @model_validator(mode="after")
    def check_discount_price(self):
        print("model after:", self)

        if self.discount_price > self.price:
            raise ValueError(
                "할인 가격은 원래 가격보다 클 수 없습니다."
            )

        return self


@app.post("/books")
def create_book(book: BookCreate):
    return book
```

- before: 데이터 전처리
- after: 데이터 전처리 이후 데이터 검증
- model_validator: 여러개 필드 검사
- field_validator: 필드 단 하나씩만 검사, 하나 이상 하려면 함수 따로 만들기

질문: 그럼 classmethod staticmethod 둘다 정적이라는 이유가 인스턴스에안묶이거나 클래스 자동으로전달안받아서 그런거임?
gpt의 답장:
거의 맞지만, 둘을 모두 “정적”이라고 부르면 정확하지 않습니다.

```text
classmethod  → 인스턴스에는 안 묶임, 클래스에는 묶임
staticmethod → 인스턴스에도 안 묶임, 클래스에도 안 묶임
```

### `@classmethod`

```python
class Book:
    category = "programming"

    @classmethod
    def show_category(cls):
        return cls.category
```

```python
Book.show_category()
```

호출하면 클래스가 자동으로 전달됩니다.

```text
cls = Book
```

따라서:

- `self`는 받지 않음
- `cls`는 자동으로 받음
- 인스턴스가 아니라 **클래스에 묶인 메서드**
- 그래서 이름이 `classmethod`

### `@staticmethod`

```python
class Book:
    @staticmethod
    def add_price(price, delivery_fee):
        return price + delivery_fee
```

호출해도 아무것도 자동 전달되지 않습니다.

```python
Book.add_price(20000, 3000)
```

```text
price = 20000
delivery_fee = 3000
```

따라서:

- `self`를 자동으로 받지 않음
- `cls`도 자동으로 받지 않음
- 특정 인스턴스나 클래스 정보에 묶이지 않음
- 그래서 `staticmethod`

### 정확한 정리

| 종류            | `self` 자동 전달 | `cls` 자동 전달 | 무엇과 연결되는가           |
| --------------- | ---------------: | --------------: | --------------------------- |
| 인스턴스 메서드 |                O |               X | 특정 객체                   |
| `classmethod`   |                X |               O | 호출한 클래스               |
| `staticmethod`  |                X |               X | 자동으로 연결되는 대상 없음 |

따라서 질문에 대한 정확한 답은:

> `classmethod`는 인스턴스에는 묶이지 않지만 클래스에는 묶입니다.
>
> `staticmethod`만 인스턴스와 클래스 어느 쪽도 자동으로 전달받지 않습니다.

둘 다 객체를 만들지 않고 호출할 수 있다는 공통점 때문에 비슷해 보이는 것입니다.

질문: 근데 왜 정적이라는말을써
codex 답변:
`static`이라는 말은 **값이 고정돼서**가 아니라, 메서드를 호출할 때 **호출 대상이 자동으로 붙지 않아서** 사용합니다.

일반 메서드를 호출하면 Python이 객체를 자동으로 붙입니다.

```python
class Book:
    def introduce(self):
        return self.title
```

```python
book.introduce()
```

Python은 이를 대략 다음처럼 처리합니다.

```python
Book.introduce(book)
#              ↑
#         객체가 자동으로 전달됨
```

어떤 객체로 호출했느냐에 따라 `self`가 달라집니다.

```python
book1.introduce()  # self = book1
book2.introduce()  # self = book2
```

반면 `staticmethod`는 호출 대상이 자동으로 붙지 않습니다.

```python
class Book:
    @staticmethod
    def add_price(price, delivery_fee):
        return price + delivery_fee
```

```python
Book.add_price(20000, 3000)
```

실제로도 다음 값만 전달됩니다.

```python
add_price(20000, 3000)
```

`Book`도 전달되지 않고 특정 객체도 전달되지 않습니다. 즉, 호출 방식이 특정 객체에 따라 연결되지 않고 **그대로 유지되기 때문에 `static`**이라고 부릅니다.

세 가지를 비교하면:

```text
book.method()
→ Book.method(book)
              ↑ self 자동 전달

Book.class_method()
→ class_method(Book)
               ↑ cls 자동 전달

Book.static_method(10)
→ static_method(10)
                ↑ 아무것도 자동 전달되지 않음
```

따라서 정확한 뜻은 다음과 같습니다.

> `static` = 값이 변하지 않는다 ❌
>
> `static` = 호출할 때 `self`나 `cls`가 자동으로 연결되지 않는다 ✅

`staticmethod`는 쉽게 말하면 **클래스라는 폴더 안에 정리해 놓은 일반 함수**입니다.
