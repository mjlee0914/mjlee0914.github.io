## 1. Path와 Query는 역할이 다르다

실습 API는 `/groceries/{item_id}`에서 `item_id`를 경로 매개변수로 받고, `keyword`를 쿼리 매개변수로 받는다.

```python
@app.get("/groceries/{item_id}")
async def get_grocery(
    item_id: Annotated[int, Path(..., description="상품 ID")],
    keyword: Annotated[Optional[str], Query(description="키워드")] = None,
):
    ...
```

요청값은 다음과 같이 들어온다.

```text
GET /groceries/2?keyword=유기농%20우유
                    ↓
item_id = 2
keyword = "유기농 우유"
```

- `item_id`는 URL 경로에서 받아 실제 상품을 찾는 데 사용한다.
- `keyword`는 `str` 또는 `None`이 될 수 있는 선택적 쿼리 매개변수다.
- `Query(description="키워드")`의 설명은 Swagger 문서에 표시된다.

하지만 값을 **받는 것**과 그 값으로 실제로 **검색하는 것**은 다르다. 오늘 코드에서 `keyword`는 로그에만 출력되므로 `/groceries/1?keyword=유기농 우유`를 요청해도 `item_id=1`인 사과가 반환된다.

이름 검색 기능을 만들려면 `/groceries?keyword=우유`처럼 별도 목록 조회 API에서 상품들을 순회하고 이름을 비교해야 한다.

```python
search_results = [
    grocery
    for grocery in grocery_database.values()
    if keyword.lower() in grocery["name"].lower()
]
```

## 2. HTTPException과 사용자 정의 예외

없는 상품 ID는 FastAPI가 제공하는 `HTTPException`으로 바로 처리했다.

```python
if item_id not in grocery_database:
    raise HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail="식료품을 찾을 수 없습니다",
    )
```

반면 유통기한 만료는 서비스에만 존재하는 규칙이므로 `GroceryExpiredException`이라는 사용자 정의 예외를 만들었다.

```python
class GroceryExpiredException(Exception):
    def __init__(self, name: str, expiration_date: date):
        self.name = name
        self.expiration_date = expiration_date
```

전체 흐름은 다음과 같다.

```text
GET /groceries/2
        ↓
2번 상품 조회
        ↓
expiration_date < date.today() 확인
        ↓
GroceryExpiredException(name, expiration_date) 발생
        ↓
등록된 exception_handler 실행
        ↓
400 JSONResponse 반환
```

```python
@app.exception_handler(GroceryExpiredException)
async def handle_exception(request: Request, exc: GroceryExpiredException):
    return JSONResponse(
        status_code=status.HTTP_400_BAD_REQUEST,
        content={
            "success": False,
            "message": (
                f"식료품 [{exc.name}]의 유통기한("
                f"{exc.expiration_date.strftime('%Y년 %m월 %d일')})이 지났습니다."
            ),
        },
    )
```

### 실습 중 발견한 오류

```python
self.expiration_date = date
```

여기서 `date`는 전달받은 날짜가 아니라 `datetime.date` 클래스다. 그래서 출력 결과가 `<class 'datetime.date'>`로 나타났다. 매개변수로 받은 값을 저장해야 한다.

```python
self.expiration_date = expiration_date
```

또한 예외 처리기에서는 원래 조회 함수의 `item` 변수를 직접 사용할 수 없다. 예외에 담아 전달한 `exc.name`, `exc.expiration_date`를 사용해야 한다.

`str(exc)`는 예외 객체를 사람이 읽을 수 있는 문자열로 바꾼다. 다만 f-string에서는 `f"{exc}"`라고 적어도 자동으로 문자열 변환이 일어난다.

## 3. 날짜 객체를 원하는 모양으로 출력하기

`date(2026, 7, 5)`를 그대로 출력하면 `2026-07-05`가 된다. `strftime()`을 사용하면 한국식 표시로 바꿀 수 있다.

```python
exc.expiration_date.strftime("%Y년 %m월 %d일")
# "2026년 07월 05일"
```

객체와 메서드 사이에는 점이 필요하다.

```python
# 잘못된 코드
exc.expiration_datestrftime(...)

# 올바른 코드
exc.expiration_date.strftime(...)
```

## 4. APIRouter로 기능 분리하기

주문 관련 경로는 별도 `router.py`에 `APIRouter`로 분리했다.

```python
router = APIRouter(prefix="/v1/order", tags=["Orders"])

@router.get("")
async def test1():
    return {"message": "test1"}
```

메인 앱에서는 라우터를 가져와 등록한다.

```python
from order.presentation.routers.v1.router import router as order_router

app.include_router(order_router)
```

`prefix`는 모든 주문 경로 앞에 `/v1/order`를 붙이고, `tags`는 Swagger 문서에서 관련 API를 같은 그룹으로 묶는다. 이렇게 하면 `main.py`에 모든 엔드포인트를 몰아넣지 않고 도메인별로 관리할 수 있다.

## 5. uv 프로젝트 경계와 폴더 depth

`chapter03-1`과 `chapter03-2`에는 각각 `pyproject.toml`이 있다. 내부 폴더라서 uv를 무조건 다시 만드는 것이 아니라, 두 실습을 서로 독립된 Python 프로젝트로 관리하기 위해 경계를 나눈 것이다.

```text
11_backend_api/                    depth 0
├── chapter03-1/                   depth 1, 독립 uv 프로젝트
│   ├── pyproject.toml
│   └── src/                       depth 2
└── chapter03-2/                   depth 1, 독립 uv 프로젝트
    ├── pyproject.toml
    └── src/                       depth 2
```

`chapter03-2/src`에서 `uv run`을 실행하면 uv는 현재 위치부터 부모 폴더로 올라가며 가장 가까운 `pyproject.toml`을 찾는다. 따라서 `chapter03-2`의 의존성인 Jinja2를 사용한다. 핵심은 폴더의 깊이 자체가 아니라 **가장 가까운 프로젝트 설정 파일의 위치**다.

## 6. 포트 충돌은 주소가 아니라 프로세스 문제다

`chapter03-1` 서버가 기본 포트 8000을 사용 중인 상태에서 `chapter03-2` 서버를 같은 포트로 실행해 `Address already in use` 오류가 발생했다.

기존 서버 터미널에서는 `Control + C`로 종료할 수 있다. 터미널을 찾기 어렵다면 포트를 점유한 프로세스를 확인한 뒤 해당 PID를 종료한다.

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
kill <확인한_PID>
```

두 서버를 동시에 실행하려면 두 번째 서버의 포트를 바꾸면 된다.

```bash
uv run uvicorn main:app --app-dir src --reload --port 8001
```

## 7. FastAPI에서 Jinja2 템플릿 렌더링하기

`chapter03-2`에서는 Python이 만든 데이터를 HTML 템플릿에 전달했다.

```python
CURRENT_DIR = os.path.dirname(__file__)
templates = Jinja2Templates(
    directory=os.path.join(CURRENT_DIR, "templates")
)
templates.env.add_extension("jinja2.ext.do")
```

- `__file__`: 현재 실행 중인 `main.py`의 경로
- `os.path.dirname(__file__)`: `main.py`가 들어 있는 폴더
- `os.path.join(...)`: 그 폴더와 `templates`를 안전하게 연결
- `jinja2.ext.do`: 템플릿에서 `{% do ... %}` 사용 허용

요청 처리 함수는 데이터를 딕셔너리로 만들고 템플릿에 `context`로 넘긴다.

```python
@app.get("/practice1", response_class=HTMLResponse)
async def jinja_practice1(request: Request):
    student_context = {
        "name": "Sparta",
        "age": 20,
        "hobbies": ["독서", "영화"],
        "nickname": None,
        "html_code": "<h2>안녕하세요!</h2>",
    }

    return templates.TemplateResponse(
        request=request,
        name="practice1.html",
        context=student_context,
    )
```

`request=request`에서 왼쪽은 `TemplateResponse`가 요구하는 인수 이름이고, 오른쪽은 함수가 받은 실제 요청 객체다. `requst=request`처럼 철자가 틀리면 예상하지 못한 키워드 인수라는 오류가 발생한다.

## 8. Jinja2 문법과 필터

템플릿은 전달받은 값을 HTML에 출력하고 조건문과 반복문을 실행한다.

```jinja2
{% if age >= 20 %}
  <p>성인: 모든 기능 사용 가능</p>
{% elif age >= 14 %}
  <p>청소년: 일부 기능 제한</p>
{% else %}
  <p>어린이: 이용 불가</p>
{% endif %}
```

```jinja2
{% for hobby in hobbies %}
  <li>{{ hobby }}</li>
{% endfor %}
```

오늘 사용한 주요 기능은 다음과 같다.

- `safe`: HTML 문자열을 일반 글자가 아닌 실제 HTML 태그로 렌더링한다. 신뢰할 수 없는 사용자 입력에는 XSS 위험 때문에 사용하면 안 된다.
- `length`: 목록의 길이를 구한다.
- `join(',')`: 목록을 쉼표로 연결한다.
- `{% set %}`: 템플릿 변수를 만든다.
- `{% with %}`: 해당 블록 안에서 사용할 지역 변수를 만든다.
- `{% do hobbies.append('운동') %}`: 값을 출력하지 않고 목록을 변경한다.

`nickname`은 정의되지 않은 값이 아니라 `None`으로 전달됐다. Jinja2의 기본 `default('익명')`은 정의되지 않은 변수에 적용되므로, `None` 같은 falsy 값에도 적용하려면 두 번째 인수로 `true`를 준다.

```jinja2
<p>닉네임: {{ nickname | default('익명', true) }}</p>
```

단, 이 방식은 `None`뿐 아니라 빈 문자열, `False`, `0`도 기본값으로 바꾼다. 정확히 `None`만 처리하려면 다음 표현이 더 명확하다.

```jinja2
{{ nickname if nickname is not none else '익명' }}
```

## 오늘의 핵심 정리

1. FastAPI가 요청값을 받아주는 것만으로 검색 기능이 완성되는 것은 아니다. 받은 값을 실제 조회 로직에 사용해야 한다.
2. `Path`는 특정 자원을 식별하고, `Query`는 검색·필터·정렬 같은 선택 조건을 전달할 때 주로 사용한다.
3. 공통 HTTP 오류는 `HTTPException`, 서비스 고유 규칙은 사용자 정의 예외와 예외 처리기로 표현할 수 있다.
4. 예외 객체에 필요한 데이터를 저장하면 발생 지점과 응답 생성 지점을 분리할 수 있다.
5. `APIRouter`는 기능별 경로를 분리하고 Swagger 문서에서도 그룹화한다.
6. uv는 폴더 depth가 아니라 가장 가까운 `pyproject.toml`을 기준으로 프로젝트를 판단한다.
7. Jinja2는 Python의 `context` 데이터를 HTML 표현으로 바꾸며, 조건문·반복문·필터를 템플릿에서 사용할 수 있다.
