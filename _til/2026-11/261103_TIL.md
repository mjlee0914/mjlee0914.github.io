## Domain-Driven Design (DDD)

DDD는 복잡한 소프트웨어를 도메인 중심으로 설계하는 접근 방식이다.  
도메인 전문가와 개발자가 **유비쿼터스 언어(Ubiquitous Language)**를 함께 사용해 소통하고, 그 언어를 설계와 코드에도 일관되게 반영한다.

### 도메인 객체

- **Entity**
  - 식별자(identity)로 구별되는 객체 - 고유 ID를 가진다
  - 예: Reservation, Ticket, Festival, Performance, User
  - 속성이 바뀌어도 같은 식별자를 유지하면 같은 Entity로 본다.
  - 정의시에 일반 클래스 혹은 `@dataclass`로 정의:
    - 반복 코드를 줄이고 순수한 도메인 객체를 간결하게 표현 가능
      ex)

```python
# 일반 클래스로 정의하는 경우
class Post:
    def __init__(self, title: str, content: str):
        self.title = title
        self.content = content
```

```python
# dataclass로 정의시
from dataclasses import dataclass

@dataclass(eq=False)
class Post:
    post_id: int
    title: str
    content: str

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Post):
            return False

        return self.post_id == other.post_id
```

- **Value Object**
  - 고유한 식별자보다 값과 속성으로 구별되는 객체
  - 같은 값을 가지고 있으면 같은 VO
  - 보통 불변(immutable) 객체로 만든다.
  - 예: Venue, Price, ReservationId, TicketId
  - `ReservationId`, `TicketId`처럼 Entity를 식별하는 ID도 Value Object로 모델링할 수 있다.

ex)

```python
from dataclasses import dataclass
from uuid import UUID

@dataclass(frozen=True)
class ReservationId:
    value: UUID
```

```python
@dataclass(frozen=True)
class Price:
    amount: int
    currency: str

    def __post_init__(self) -> None:
        if self.amount < 0:
            raise ValueError("가격은 0보다 작을 수 없습니다.")
```

- frozen=True로 생성 후 필드 변경 제한 -> immutability 표현

### Aggregate

- Aggregate는 관련된 Entity와 Value Object를 하나의 **일관성 경계(consistency boundary)**로 묶은 단위다.
- Aggregate 내부의 불변 조건(invariant)은 Aggregate Root를 통해 보호한다.
- 각 Aggregate에는 외부에서 접근하는 진입점인 **Aggregate Root**가 하나 있다. Root는 보통 Entity다.
- Aggregate 내부 객체는 Aggregate Root를 통해 접근하고 변경한다.
- 다른 Aggregate를 참조할 때는 객체 전체보다 해당 Aggregate Root의 식별자를 참조하는 것이 일반적이다.

Ex)

- Aggregate Root: Reservation일 때 다음처럼 Aggregate Root를 통해 상태 변경한다.

```python
class Reservation:
    def cancel(self) -> None:
        if self.status == "completed":
            raise ValueError("완료된 예약은 취소할 수 없습니다.")

        self.status = "cancelled"
```

```python
reservation.add_ticket(ticket)
reservation.cancel()
```

- 아래처럼 외부에서 내부 값을 직접 변경하지 않는다.

```python
reservation.status = "cancelled"
```

### Repository

- Repository는 Aggregate를 저장하고 다시 불러오는 추상화다.
- 보통 Aggregate Root 단위로 Repository를 둔다.
- 도메인 계층에서는 저장 기술이나 SQLAlchemy 같은 인프라 기술을 알지 않아도 된다.
- Repository 인터페이스는 도메인 또는 애플리케이션 계층에 두고, 실제 DB 접근 구현은 인프라 계층에 둘 수 있다.
- Repository는 저장·조회 경계를 제공한다.
- Aggregate의 유효한 상태와 불변 조건은 Aggregate Root가 보장한다.

ex)

```python
from typing import Protocol

class ReservationRepository(Protocol):
    def save(self, reservation: Reservation) -> None:
        ...

    def find_by_id(
        self,
        reservation_id: ReservationId,
    ) -> Reservation | None:
        ...
```

---

-> 그럼 DDD는 4계층 구조에서 어떻게 정의되나?

```
API 요청
  ↓
Presentation 계층 : HTTP요청/응답 처리: 요청을 어떻게 받고 응답할까?
  ↓
Application 계층 : 유스케이스 진행 순서 조율:  무엇을 어떤 순서로 실행하나?
  ↓
Domain 계층 : 업무 규칙과 도메인 모델: 무엇이 허용되나?
  ↑
Infrastructure 계층 : DB/외부 서비스 구현: DB에 어떻게 저장할까?
  ↓
데이터베이스

```

#### 4계층 구조 예시

1. presentation

```python
@router.patch("/reservations/{reservation_id}/cancel")
async def cancel_reservation(
    reservation_id: UUID,
    service: ReservationService = Depends(),
):
    await service.cancel(reservation_id)

    return {"message": "예약이 취소되었습니다."}
```

2. application

```python
class ReservationService:
    def __init__(
        self,
        reservation_repository: ReservationRepository,
    ):
        self.reservation_repository = reservation_repository

    async def cancel(self, reservation_id: UUID) -> None:
        reservation = await self.reservation_repository.find_by_id(
            ReservationId(reservation_id)
        )

        if reservation is None:
            raise ReservationNotFoundError()

        reservation.cancel()

        await self.reservation_repository.save(reservation)
```

3. domain

- VO

```python
from dataclasses import dataclass
from uuid import UUID

@dataclass(frozen=True)
class ReservationId:
    value: UUID
```

- Aggregate Root/Entity

```python
from dataclasses import dataclass

@dataclass(eq=False)
class Reservation:
    id: ReservationId
    status: str

    def cancel(self) -> None:
        if self.status == "completed":
            raise ValueError("완료된 예약은 취소할 수 없습니다.")

        if self.status == "cancelled":
            raise ValueError("이미 취소된 예약입니다.")

        self.status = "cancelled"
```

- Repository Interface

```python
from typing import Protocol

class ReservationRepository(Protocol):
    async def find_by_id(
        self,
        reservation_id: ReservationId,
    ) -> Reservation | None:
        ...

    async def save(
        self,
        reservation: Reservation,
    ) -> None:
        ...
```

- domain 계층에서는 Repository가 무엇을 할 수 있는지만 정의한다
- domain 계층에서는 SQLAlchemy, PostgreSQL을 알 필요가 없다

4. infrastructure

- domain 계층에서 정의한 Repository를 실제로 구현한다
- SQLAlchemy 쿼리 실행
- DB데이터 조회 및 저장
- ORM모델과 domain entity간 변환
- 외부 API나 메시지 시스템 연결

```python
class SqlAlchemyReservationRepository:
    def __init__(self, session: AsyncSession):
        self.session = session

    async def find_by_id(
        self,
        reservation_id: ReservationId,
    ) -> Reservation | None:
        orm_reservation = await self.session.get(
            ReservationORM,
            reservation_id.value,
        )

        if orm_reservation is None:
            return None

        return Reservation(
            id=ReservationId(orm_reservation.id),
            status=orm_reservation.status,
        )

    async def save(self, reservation: Reservation) -> None:
        orm_reservation = await self.session.get(
            ReservationORM,
            reservation.id.value,
        )

        orm_reservation.status = reservation.status
        await self.session.commit()
```

전체 요청 흐름도

```
① Presentation
   예약 취소 HTTP 요청을 받는다.
        ↓
② Application
   Repository로 Reservation을 조회한다.
        ↓
③ Infrastructure
   SQLAlchemy를 사용해 DB에서 데이터를 읽는다.
        ↓
④ Domain
   DB 데이터를 Reservation Aggregate로 복원한다.
        ↓
⑤ Application
   reservation.cancel()을 호출한다.
        ↓
⑥ Domain
   취소 가능 여부를 검사하고 상태를 변경한다.
        ↓
⑦ Application
   Repository의 save()를 호출한다.
        ↓
⑧ Infrastructure
   변경된 상태를 DB에 저장한다.
        ↓
⑨ Presentation
   HTTP 응답을 반환한다.
```

| 개념                          | 주로 위치하는 계층 | 역할                           |
| ----------------------------- | ------------------ | ------------------------------ |
| API Router, 요청·응답 Schema  | Presentation       | HTTP 요청과 응답 처리          |
| Application Service, Use Case | Application        | 작업 순서와 트랜잭션 조정      |
| Entity                        | Domain             | 식별자를 가진 도메인 객체      |
| Value Object                  | Domain             | 값으로 구별되는 불변 객체      |
| Aggregate Root                | Domain             | Aggregate의 상태와 규칙 보호   |
| Repository 인터페이스         | Domain             | 저장·조회 기능의 추상화        |
| Repository 구현체             | Infrastructure     | SQLAlchemy 등으로 실제 DB 접근 |
| ORM Model                     | Infrastructure     | DB 테이블 매핑                 |
