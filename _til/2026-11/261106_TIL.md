# 2026-11-06 개인 작업일지

## what/how

- 출근 후 먼저 프로젝트의 ERD 맵을 Notion에서 최신 내용으로 업데이트함.
- Festival의 취소 시각을 나타내는 nullable `canceled_at`이 모델·도메인·응답 스키마에서 일관되게 사용되는지 확인함. 모델 컬럼 자체는 11월 4일 커밋에 포함되어 있으므로 11월 6일의 신규 구현과 구분함.
- Performance 도메인 엔티티를 구현함. 공연 일정, 예매 기간, 수용 인원, 잔여 수량, 가격과 상태를 순수 Python 객체로 표현함.
- 공연 생성 시 공연 시간이 Festival 기간 안에 있는지, 예매 기간이 올바른지, 수량과 가격이 유효한지 검사하는 규칙을 추가함.
- `SCHEDULED`, `OPEN`, `SOLD_OUT`, `CANCELED`, `COMPLETED` 상태 전이와 예매 가능 여부 판단 규칙을 정리함.
- 잘못된 일정·수량·가격·상태 전이에 대응하는 Performance 도메인 예외를 정의함.

## blockers/concerns

- Performance가 Festival 엔티티에 직접 의존하면 도메인 간 결합이 커질 수 있어, 축제 기간을 어떤 형태로 전달할지 결정해야 했음.
- 현재 시각을 엔티티 내부에서 직접 생성하면 테스트 시각을 고정하기 어렵고, 상태 전이 검증도 불안정해질 수 있었음.
- 11월 4일에 작성된 Festival `canceled_at` 변경과 11월 6일 Performance 구현을 같은 날의 신규 작업처럼 기록하지 않도록 구분이 필요했음.

## resolution

- Festival 객체 전체를 넘기지 않고 `festival_starts_on`, `festival_ends_on` 날짜 값만 Performance 생성 규칙에 전달해 의존 방향을 단순하게 유지함.
- 상태 변경 메서드는 현재 시각을 인자로 받도록 설계해 규칙을 재현 가능하게 만들고 테스트에서 원하는 시점을 주입할 수 있게 함.
- 데이터 유효성 검사는 엔티티 생성과 상태 전이 메서드 안에 모아, Router나 Service가 규칙을 우회하지 않도록 함.

## verification

- 본인 저자 커밋 `e5972d8`에서 Performance 도메인 엔티티·예외·상태 전이 구현을 확인함.
- 같은 날 `dev` 병합 내용을 작업 브랜치에 반영한 커밋 `c5c3772`가 확인됨.
- Festival `canceled_at` 모델 변경은 11월 4일 커밋 `dba353a`와 `9f95efd`에서 확인되며, 11월 6일 신규 구현으로 보지는 않음.
- 이 시점 기록에서는 별도의 전체 테스트 통과나 API 실행 검증을 확인하지 못했으므로 구현 완료와 동작 검증을 구분함.
