# 2026-11-09 개인 작업일지

## what/how

- 축제 리뷰 사소한 지적사항을 반영해 축제 PR #110을 dev에 머지함.
- 축제 취소 정책(#112)을 구현함. 취소되지 않은 공연이 있으면 축제 취소를 409(`FESTIVAL_HAS_UNCANCELED_PERFORMANCES`)로 막고, 기간 밖 공연 검사는 공연 전체 조회 대신 `EXISTS` 한 번으로 바꿈. PR #118을 올림.
- 팀 회의에서 `Annotated` 의존성, `/v1` 접두사, 상태 변경 API는 `PATCH`, `routers/v1/router.py` 구조, KST 공용 유틸 사용, 취소 시 예매 일괄 취소(양일권은 전체 취소)를 정함.
- 공연 API(#111)를 service → dependencies → wiring → router 순서로 직접 작성함. 엔드포인트는 생성·목록·상세·수정·오픈·취소·종료·예매 가능 여부 8개임.
- 회의 결정에 맞춰 축제·공연 router를 `routers/v1/router.py`로 옮기고, 축제 취소 API를 `PATCH`로 바꿈.
- #118 리뷰를 반영함. dev merge 충돌을 정리하면서 `shared/core/time.py`(`KST`, `now_utc()`)로 교체하고, "이미 취소됨" 검사를 `Festival.ensure_not_canceled()` 한 곳으로 모음.
- 같은 메서드를 공연 생성에도 써서 취소된 축제에는 공연을 만들 수 없게 함. `main.py`에 축제·공연 router를 등록하고 PR #132를 올림.
- 후속 작업은 이슈로 분리함: 관리자 권한 검사(#119), 공연·축제 취소 시 예매 일괄 취소(#131).

## blockers/concerns

- **관리자 구분:** `UserRole` enum이 있는데 `require_admin_role`이 왜 따로 필요한지 헷갈렸음.
- **정의와 호출 혼동:** repository의 정의(`exclude_id: int | None = None`)를 호출하는 쪽에 그대로 복사해서 SyntaxError가 남. 그 전에는 `exclude_id=int`처럼 타입 자체를 값으로 넘김.
- **`self` 직접 전달:** `self._repo.method(self, ...)`처럼 `self`를 넘겨서 "got multiple values" 에러가 남.
- **`Performance(...)`로 직접 생성:** `Performance.create(...)` 대신 써서 축제 기간 검사를 건너뜀. 에러 없이 저장되는 버그라 위험했음.
- **복사 붙여넣기 실수:** 공연 `count`를 축제 저장소에서 셈, open/cancel/complete가 모두 `update_performance`를 부름, wiring에서 축제 저장소 자리에 공연 저장소를 넣음. 모두 에러 없이 틀린 값을 내는 종류였음.
- **조건 뒤집힘:** `if festival is not None: raise FestivalNotFound()`로 써서 정상 요청이 모두 404가 됨.
- **create의 `festival_id`:** 스키마에서 `festival_id`를 뺀 뒤 어디서 받아야 하는지 몰라서 막힘.
- **`Query`의 역할:** 왜 쓰는지 이해가 안 됐음.
- **메서드를 f-string에 넣음:** 에러 메시지에 `self.status`(메서드)를 넣어서 `<bound method ...>`가 사용자에게 그대로 노출될 뻔함.

## resolution

- **enum과 `require_admin`:** enum은 "명찰"(값), `require_admin`은 명찰을 보고 막는 "경비원"(검사)으로 이해함. "본인 또는 관리자"처럼 대상이 있어야 판단할 수 있는 규칙은 라우터가 아니라 도메인 메서드에 둠.
- **정의와 호출:** 정의는 `이름: 타입 = 기본값`, 호출은 `이름=값`임. 기본값이 이미 `None`이면 호출할 때 아예 넘기지 않으면 됨.
- **`self`:** 점(`.`)으로 메서드를 부르면 파이썬이 `self`를 자동으로 넣어 줌.
- **생성은 `create`로:** 엔티티는 `create`를 거쳐야 모든 규칙 검사를 통과함. 축제 기간은 이미 꺼낸 `festival`의 `starts_on`, `ends_on`을 넘김.
- **수정할 때 축제는 공연에서 꺼내기:** 축제는 요청이 아니라 `performance.festival_id`로 꺼냄. 요청에 다른 축제 id를 넣어 기간 검사를 통과하는 것을 막을 수 있음.
- **함수 인자가 오는 곳:**
  - 경로에 `{이름}`이 있으면 경로 (`Path`)
  - int, str 같은 단순 값이면 쿼리 (`Query`)
  - Pydantic 모델이면 JSON body (스키마의 `Field`)
  - `Query`/`Path`/`Field`는 최소·최대 같은 규칙을 붙일 때만 씀. 규칙을 어기면 함수 실행 전에 422로 돌려보냄. 예를 들어 `page=0`이면 음수 OFFSET으로 500이 날 상황을 422로 막음.
- **응답 만들기:** 엔티티 필드와 응답이 같으면 `model_validate(entity)`를 쓰고, `is_bookable`처럼 계산한 값이 섞이면 응답 객체를 직접 채움. 값 두 개를 돌려줄 때는 `tuple`로 반환하고 `a, b = ...`로 받음.
- **시간은 service가 정함:** 현재 시각은 service가 `now_utc()`로 만들어 엔티티에 넘김. router는 시간을 다루지 않음.
- **규칙은 한 곳에:** 같은 규칙이 service와 엔티티 두 곳에 있으면, 엔티티에 `ensure_...()` 메서드를 만들어 둘 다 그걸 부르게 함 (users의 `ensure_active()`와 같은 패턴).
- **merge 충돌:** `<<<<<<<`(내 쪽) / `=======` / `>>>>>>>`(dev 쪽)을 보고, 실제로 쓰는 import가 무엇인지 확인한 뒤 골랐음. 한쪽을 통째로 고르면 다른 쪽 코드가 쓰는 import가 사라질 수 있음.

## verification

- 테스트용 앱(router + wiring + 예외 핸들러, `get_db`를 savepoint로 override, 끝나면 rollback)으로 도커 PostgreSQL에서 공연 API 20개 시나리오와 축제 API 6개 시나리오가 통과함.
- 로컬 DB에는 테이블이 없음. 마이그레이션 도구가 없어서 테스트 트랜잭션 안에서 만들고 rollback함. 테이블 생성 방식은 팀에 확인이 필요함.
- `uvicorn`으로 서버를 띄워 Swagger에 festivals, performances 엔드포인트가 보이는 것을 확인함.
- `ruff`는 바꾼 파일 기준으로 통과함. 프로젝트 전체에는 다른 도메인의 기존 경고가 남아 있고, `main.py`에는 원래 위치에서 주석만 해제해서 import 순서 경고 1개가 있음.
- 에디터에서 저장하지 않아 수정이 반영되지 않은 적이 있음. 확인을 요청하기 전에 저장했는지 먼저 볼 것.
- 남은 일: #118 머지 확인 → #132 리뷰 대응, #119 관리자 검사(users 관리자 검증 #123 활용 검토), #131 예매 일괄 취소의 환불 여부와 호출 주체 협의, 축제별 공연 목록 URL 최종 확인.
